Fashion-CLIP — describe it, find it

CLIP learns a shared space for images and text, so you can search a collection of pictures with a sentence. Fashion-CLIP is a CLIP model fine-tuned on fashion pairs. This demo embeds a small catalog once, then ranks it against your free-text query — every score is a real cosine similarity, computed on your device.

See inside — the shared embedding space

Every image and every query becomes a vector (512-dim after projection). The rank is the cosine similarity between the query vector and each image vector — 1.0 means identical direction, 0 means unrelated. The scores below each card are that real number; nothing is faked. Because Fashion-CLIP was tuned on clothing pairs, fashion-y queries are its specialty — try "a formal outfit" and see what it does with this catalog.

Why it matters

Text→image retrieval is the engine behind visual search and media library tools. Running it on-device means a photo collection is searchable by description without uploading a single image.

  • Private photo search — "find the picture of the beach trip" over your own library, offline.
  • Catalog & DAM tools — rank assets by natural-language descriptions instead of tags.
  • Zero-shot tagging — generate relevance scores for arbitrary labels with no training.
  • Domain-tuned CLIP — a concrete example of fine-tuning a general model to a vertical.

How the API works

import { AutoTokenizer, AutoProcessor, CLIPModel } from "@huggingface/transformers";

const tokenizer = await AutoTokenizer.from_pretrained(MODEL, { subfolder: "onnx" });
const processor = await AutoProcessor.from_pretrained(MODEL, { subfolder: "onnx" });
const model = await CLIPModel.from_pretrained(MODEL, { subfolder: "onnx", dtype: "fp32" });

const imageInputs = await processor(await Promise.all(urls.map(RawImage.read)));
const textInputs = await tokenizer([query], { padding: true, truncation: true });
const { image_embeds, text_embeds } = await model({ ...textInputs, ...imageInputs });
// rank = cosine(text_embeds[0], image_embeds[i]) for each catalog image

We embed the catalog once (it's cached in the worker), then each query is a single text pass + a cosine sweep — fast enough for interactive search. All of it runs in a Web Worker.
