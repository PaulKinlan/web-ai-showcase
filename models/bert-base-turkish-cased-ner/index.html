Turkish NER — find the names hiding in a sentence

Where POS tagging labels every word's grammatical role, named-entity recognition (NER) hunts a narrower quarry: the proper names. Who is this text about? Which companies, which places? This model reads Turkish and hands back each person, organisation, location name it finds in its trained PER / ORG / LOC label set, with a confidence. Type below and watch the entities light up inline, then look inside at the raw per-token labels. All on your device.

Honest note on language: this runs akdeniz27/bert-base-turkish-cased-ner, the canonical Turkish BERTurk NER repository at immutable revision 99995f7…. The showcase already has English and multilingual BERT NER; this is the Turkish BERTurk family, so the examples are in Turkish with an English gloss. The capability — finding typed names in running text — is the same in any language.

See inside — raw labels & detected entities

The model doesn't see whole words — it labels each WordPiece sub-token independently (a ## prefix, shown here as ·, marks a continuation) with one of O plus BIO person, organisation and location labels. We merge the pieces back into words, then group consecutive same-type words into entity spans — so Tan · pınar becomes one person word before BIO spans are formed. Why it matters

Named entities are the skeleton of meaning in news, mail, documents and chat. Once you know who and where a text talks about, you can index it, redact it, link it or summarise around it — and doing it in the browser means the text never leaves the device.

  • Document indexing & search — pull the people, orgs and places as faceted metadata for a knowledge base.
  • Privacy redaction — find every person or organisation name so it can be masked before a document is shared.
  • News & mail triage — "who is this about?" is often the whole question; entities answer it in one pass.
  • Downstream NLP — entity spans feed relation extraction, coreference, knowledge-graph building and smarter summarisation.

How the API works

The canonical repository uses a root model.onnx, so this demo pairs the exact cased tokenizer with raw ORT-Web rather than pretending it has a Transformers.js ONNX layout:

const tokenizer = await AutoTokenizer.from_pretrained(
  "akdeniz27/bert-base-turkish-cased-ner",
  { revision: "99995f7d2be4b3a28c74f0d36ee97f8c04ee0571" }
);
const session = await ort.InferenceSession.create(modelBytes, {
  executionProviders: ["wasm"]
});
const logits = (await session.run(toOrtFeeds(await tokenizer(text)))).logits;
// logits shape: [batch, WordPieces, 7 BIO labels]

The worker aligns exact cased WordPieces back to the original Turkish string, merges ## continuations, and aggregates BIO labels. Raw pieces, labels, scores and exact character spans remain inspectable. Loading is intentionally explicit because 420 MiB is not a polite surprise on a phone.
