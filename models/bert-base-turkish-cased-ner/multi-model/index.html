Route Turkish text before extracting its entities

Language identification is a useful guardrail for a language-specific model. A multilingual XLM-R classifier first scores the input across 20 languages. The canonical Turkish BERT NER then extracts exact spans. If Turkish is not the top language, the page still lets you inspect the NER result but labels it out-of-domain instead of pretending it is reliable.

Two real downloads: about 270 MiB for language ID plus 420 MiB for Turkish NER. This composition is best prepared on desktop/Wi-Fi. It is a routing hint, not a security boundary: code-switching and short text can fool language ID, and NER can miss names.

Why compose these models?

A language router prevents accidentally treating an English or mixed-language result as if it came from the Turkish model's intended domain. It can route Turkish text to this specialist, another language to its own model, or mixed text to review. Both stages remain inspectable and run in separate workers, so neither inference pass blocks interaction.
