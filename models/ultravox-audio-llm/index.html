audio-text-to-text · audio + text → text · WebGPU · ~1.5 GB

A language model that hears you

Speak to this page and the model answers your audio — not a transcript of it. Ultravox projects the sound of your voice straight into the language model's embedding space, so the LLM attends to the recording itself. Nothing here converts speech to text at any point. Then it calls a real tool based on what it heard, and the tool really runs.

Unverified — not yet published

This page is not linked from the catalogue. It is wired to the real model and is honest about every state, but the chain has not yet been run end to end on a device with WebGPU and a microphone. Until that pass is recorded, treat anything you see here as unproven. Nothing is faked: if a stage fails, it says so.

    See inside: where the audio actually goes

    This is the part worth staring at. A speech-to-text pipeline would show you a string. There is no string here. UltravoxProcessor converts your audio to audio_values and expands the single <|audio|> placeholder into one token position per embedding frame; the model then swaps those positions for the projected audio embeddings and the decoder attends to them exactly as it would to words.

    Each turn below reports how many positions your voice occupied. Roughly one frame per 160 ms of speech — so a four-second sentence becomes about 26 positions in the prompt, none of which is a word. That is why tone, hesitation and emphasis survive: nothing ever collapsed them into text.

        Why this matters

        Every voice assistant you have used is really two systems: one that turns sound into words, and one that reads the words. That seam is where most of the information goes. The transcript keeps what you said and throws away almost everything about how — the hesitation before a number, the rising tone that made it a question, the second speaker talking over you, the accent the recogniser guessed wrong and silently committed to.

        Removing the seam changes what is buildable. And doing it on-device changes who can build it: no per-minute ASR bill, no audio leaving the machine, no server at all.

        • Intent that survives ambiguity. "Set it for two… no, five minutes" is one sentence to a model that hears it, and a mess to a transcript.
        • Audio nobody may upload. Clinical, legal and HR conversations can be acted on without the recording ever becoming someone else's log line.
        • Sounds that aren't words. The same input path carries a cough, a dog, a machine — a transcriber has nothing to say about any of them.
        • One model, one prompt. No ASR to tune, no error-propagation between stages.

        How the API works

        The processor takes text and audio. The text must contain the <|audio|> placeholder; the processor expands it to one position per embedding frame, and UltravoxModel splices the audio embeddings in at those positions. 

        import { UltravoxProcessor, UltravoxModel } from "@huggingface/transformers";

const processor = await UltravoxProcessor.from_pretrained(MODEL_ID);
const model = await UltravoxModel.from_pretrained(MODEL_ID, {
  device: "webgpu",
  dtype: { embed_tokens: "q8", audio_encoder: "q4", decoder_model_merged: "q4" },
});

const messages = [
  { role: "system", content: "You are a voice assistant running in the browser." },
  { role: "user",   content: "<|audio|>" },   // the audio IS the user's message
];

// Llama-3.2's template serialises `tools` into the first user turn.
const text = processor.tokenizer.apply_chat_template(messages, {
  tools, add_generation_prompt: true, tokenize: false,
});

// pcm is a 16 kHz mono Float32Array straight off the microphone. It never becomes text.
const inputs = await processor(text, pcm);
const ids = await model.generate({ ...inputs, max_new_tokens: 192, do_sample: false });

const out = processor.batch_decode(ids.slice(null, [inputs.input_ids.dims.at(-1), null]));
// → {"name": "start_timer", "parameters": {"seconds": 300, "label": "pasta"}}

        inputs.audio_token_len tells you how many positions the audio took. Greedy decoding (do_sample: false) matters — sampling makes a 1B model mangle the call JSON.
