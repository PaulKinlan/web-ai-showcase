What kind of “gibberish” does this model see?

Run the canonical four-class DistilBERT model locally and inspect its competing scores for clean, mild gibberish, noise, and word salad. It is a narrow input-quality signal—not a universal spam, fraud, abuse, or safety detector.

English-domain limits and false positives

The model card describes an English detector trained on madhurjindal/autonlp-data-Gibberish-Detector. Short replies, names, other languages, code, identifiers, URLs, accessibility shorthand, spelling differences, and deliberately playful writing can be meaningful yet score as gibberish. Treat scores as review signals, validate on your own traffic, provide an override, and never use this alone for account, moderation, or safety decisions.

The classifier emits four raw logits. A softmax turns them into competing probabilities that sum to one; your threshold changes only the visible product policy, never the model output. Token chips below are the actual WordPiece inputs, including special tokens.

Run an input to reveal tensor shape, token count, latency, backend, and dtype.

Why this narrow signal can matter

  • Offer a clarification prompt before sending an incoherent chatbot query downstream.
  • Route questionable form submissions to review without uploading text to a third party.
  • Audit a dataset for likely encoding or copy/paste failures while retaining human review.

How the API works

const detector = await pipeline("text-classification",
  "madhurjindal/autonlp-Gibberish-Detector-492513457",
  { revision: "76672dd7d3575f68ab980705bcec975cc62de71c", dtype: "fp32" });
const scores = await detector(text, { top_k: null });

This showcase uses the lower-level tokenizer and sequence-classification model in a versioned worker so it can expose real token IDs, logits, tensor shape, cancellation, bounded queuing, and deterministic release.
