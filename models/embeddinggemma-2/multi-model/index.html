Why two runtimes and sequential memory release matter

Comparing two model generations honestly on-device requires two completely separate runtime environments. EmbeddingGemma v1 uses the shared Transformers.js 3.7.5 pipeline with the ONNX Runtime Web WASM execution provider, while EmbeddingGemma 2 requires Transformers.js 4.3.1 running on WebGPU. Isolating each model in its own dedicated Web Worker prevents conflicting module scopes and colliding ONNX Runtime sessions.

Holding both models in browser memory simultaneously is the expensive case: downloading and maintaining both (v1 at ~314 MB q8 and v2 at ~175 MB q4) totals ~489 MB of transfer plus corresponding memory allocations. On mobile or constrained devices, concurrent allocation risks out-of-memory crashes. Sequential unloading — releasing the active model's worker, sessions, and memory buffers before loading the other — is what keeps multi-model evaluation practical and survivable on consumer hardware.
