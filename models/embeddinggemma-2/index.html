EmbeddingGemma 2 — one vector space for four modalities

Every other embedder here reads one modality. EmbeddingGemma 2 (Google DeepMind, 2026) puts text, code, images, video frames and audio into the same 768-dimensional space, so a sentence can rank a photograph and a photograph can rank a passage. It is built from a 270M text backbone with separately loadable vision and audio encoders — you download only the ones you use — and it is Apache-2.0. Search across passages below, watch the similarity matrix, then shrink the vector to 128 dimensions. Nothing leaves your device.

Two measured facts that shaped this page. (1) This export only runs on WebGPU. The q4/q8 builds block-quantize the 262,144-entry embedding table, and the ONNX Runtime Web WASM execution provider has no kernel for that op — session creation fails with GatherBlockQuantized … /model/embed_tokens/Gather_Quant. The fp32 export does load on WASM, but that is 1085 MB for the text encoder alone. The WASM path is therefore reported as blocked rather than papered over. (2) fp16 is off the table: the model card warns the activation range exceeds fp16's dynamic range and the model then returns NaN or silently degraded vectors instead of raising, and this adapter refuses fp16 outright (The device (webgpu) does not support fp16).

Selective encoder loading — the actual on-device budget

The text backbone is always loaded. The vision and audio encoders are independent graphs you can leave on the shelf: dropping their configs before the model is created means their files are never fetched. This is why the same model is a 175 MB text embedder or a 473 MB four-modality embedder.

Matryoshka — how much survives truncation?

The first 512 / 256 / 128 numbers of the vector are each trained to be a usable embedding on their own. Pick two passages, truncate both to each size, re-normalize, and compare — this is the same measurement Google publishes in the model card, on your own text.

Why it matters

Multimodal retrieval has meant two models and a projection layer: one encoder for text, one for images, trained to agree. EmbeddingGemma 2 removes that seam — one model, one 768-d space, four modalities — and it is small enough to ship in a tab, so the index never leaves the device.

  • Search your photo library by description — "two cats asleep on a couch" ranks your own images, locally, with no upload and no OCR step.
  • Search a photo to find the writing about it — the reverse direction, in the same index: give it an image and rank your notes, tickets or documentation.
  • One index for mixed media — a support corpus with screenshots, recordings and text collapses into a single vector store instead of three.
  • Right-size the download — text-only for a search box, add vision only on the screen that needs it; the budget is an explicit choice with a measured price.
  • Shrink the store 6× — Matryoshka-truncate to 128-d for constrained devices and keep most of the retrieval quality.

How the API works

Unlike the single-graph embedders, this one needs AutoModel directly rather than the feature-extraction pipeline — the pipeline loads every encoder, which defeats selective loading. Dropping the unused configs before the model is created is what keeps the text-only page at 175 MB: 

import { AutoConfig, AutoModel, AutoTokenizer } from "@huggingface/transformers@4.3.1";

const model_id = "onnx-community/embeddinggemma-2-ONNX";

const config = await AutoConfig.from_pretrained(model_id);
config.vision_config = config.audio_config = null;   // text-only: never fetch those graphs

const model = await AutoModel.from_pretrained(model_id, {
  config,
  device: "webgpu",
  dtype: { model: "q4" },          // fp16 is unsafe for this model — do not use it
});
const tokenizer = await AutoTokenizer.from_pretrained(model_id);

// Task prefixes are part of using the model correctly.
const texts = [
  "task: search result | query: Which planet is known as the Red Planet?",
  "title: none | text: Mars, known for its reddish appearance, is often referred to as the Red Planet.",
];
const { sentence_embedding } = await model(await tokenizer(texts, { padding: true, truncation: true }));
// -> [2, 768], already L2-normalized, so cosine similarity is a dot product.

// Matryoshka: keep the leading 256 numbers and re-normalize.
const small = sentence_embedding.slice(null, [0, 256]).normalize(2, -1);

Images and video frames go through AutoProcessor plus the same model(...) call, so their vectors land in the same space as the text vectors. The worker owns all of this and reports which graphs the session actually contains; see the Wild page for the cross-modal path.
