EmbeddingGemma 2 — instruction-tuned text embeddings in 768 dimensions

EmbeddingGemma 2 (Google DeepMind, 2026) maps text and code into a 768-dimensional space with instruction task prefixes. It is built from a 270M text backbone (130M transformer + 140M embedder) and released under Apache-2.0. Search across passages below, watch the similarity matrix, then shrink the vector to 128 dimensions via Matryoshka representation learning. Nothing leaves your device.

Two measured facts that shaped this page. (1) This export only runs on WebGPU. The q4/q8 builds block-quantize the 262,144-entry embedding table, and the ONNX Runtime Web WASM execution provider has no kernel for that op — session creation fails with GatherBlockQuantized … /model/embed_tokens/Gather_Quant. The fp32 export does load on WASM, but that is 1085 MB for the text encoder alone. The WASM path is therefore reported as blocked rather than papered over. (2) fp16 is off the table: the model card warns the activation range exceeds fp16's dynamic range and the model then returns NaN or silently degraded vectors instead of raising, and this adapter refuses fp16 outright (The device (webgpu) does not support fp16).

Matryoshka — how much survives truncation?

The first 512 / 256 / 128 numbers of the vector are each trained to be a usable embedding on their own. Pick two passages, truncate both to each size, re-normalize, and compare — this is the same measurement Google publishes in the model card, on your own text.

Why it matters

On-device text embeddings usually require balancing model size, context length, and licensing. EmbeddingGemma 2 combines a compact 270M text backbone, Apache-2.0 licensing, instruction-tuned task prefixes, and flexible Matryoshka truncation, all running client-side on WebGPU.

  • Task-specific embeddings — instruction prefixes let the same model specialize for symmetric similarity, search queries, document indexing, or classification.
  • Cross-lingual retrieval — 100+ languages share a single 768-d vector space. The Wild page measures cross-lingual retrieval across eight short passages in eight languages retrieved by a query written in a different language, in one pass with no translation step (with the honest caveat that the measured top-1 may not be the intended cross-lingual target).
  • Shrink the store 6× — Matryoshka-truncate to 128-d for constrained devices and keep most of the retrieval quality.
  • Permissive Apache-2.0 license — unlike earlier Gemma releases, EmbeddingGemma 2 is published under Apache-2.0 for commercial and local deployment.
  • Private on-device execution — passages and queries never leave the visitor's browser or device.

How the API works

EmbeddingGemma 2 uses AutoModel with Transformers.js 4.3.1 on WebGPU to produce 768-dimensional embeddings from text with task-instruction prefixes: 

import { AutoModel, AutoTokenizer } from "@huggingface/transformers@4.3.1";

const model_id = "onnx-community/embeddinggemma-2-ONNX";

const model = await AutoModel.from_pretrained(model_id, {
  device: "webgpu",
  dtype: { model: "q4" },          // fp16 is unsafe for this model — do not use it
});
const tokenizer = await AutoTokenizer.from_pretrained(model_id);

// Task prefixes are part of using the model correctly.
const texts = [
  "task: search result | query: Which planet is known as the Red Planet?",
  "title: none | text: Mars, known for its reddish appearance, is often referred to as the Red Planet.",
];
const { sentence_embedding } = await model(await tokenizer(texts, { padding: true, truncation: true }));
// -> [2, 768], already L2-normalized, so cosine similarity is a dot product.

// Matryoshka: keep the leading 256 numbers and re-normalize.
const small = sentence_embedding.slice(null, [0, 256]).normalize(2, -1);

Text passages and queries pass through AutoTokenizer and the model(...) call to produce 768-d unit embeddings. See the Wild page for cross-lingual retrieval across eight languages in one pass with no translation step and Multi-model for comparing v1 and v2 on the same corpus.
