Multi-model · MPNet + cross-encoder · WASM

Retrieve with MPNet, then rerank

This is how real search works. Stage one: all-mpnet-base-v2 embeds the query and every passage independently and ranks by cosine — fast, cheap, scales to millions. Stage two: a pinned MS MARCO cross-encoder (Xenova/ms-marco-MiniLM-L-6-v2 @ a09144355, q8, 23,143,499 bytes) reads the query and each shortlisted passage together and re-scores them — slower, but can be more precise. Both models run locally. The order may change between the two stages — and when it does not, we say so plainly.

Why two stages

A bi-encoder (MPNet) turns every document into a vector once, so retrieval is just nearest-neighbour math — it scales, but the query and document never "see" each other. A cross-encoder attends across the pair, catching relevance a cosine can miss, but it must run the model for every candidate — too slow for a whole corpus. Retrieve wide and cheap, rerank narrow and sharp. When the two methods agree, the order is unchanged; when they disagree, the cross-encoder reorders the shortlist.
